# ATリザルトと獲得カウンターの手取り表示

2026-10-12。表示集計のみの修正。払い出し、実BET、AT残pt、抽選・乱数消費、ストック、コンプリート条件は変更しない。

## 原因

- AT終了リザルトは `totalPaid - resultAtStartPaid` で総払い出しだけを集計し、BET代を差し引いていなかった。現在のリプレイ3pt払い戻しも獲得として増加していた。
- 下部カウンターも総払い出しだけだった。こちらは初当たりのボーナス準備から集計する一方、リザルトはボーナス終了後からで、集計開始点も一致していなかった。

## 修正

初当たりのボーナス準備から、ボーナス・初期pt決定・AT・特化・上位チャレンジ・引き戻しを含む一連の実増分を、共通の払い出し／BET開始値から計算する。

`獲得pt = max(0, (現在の総払出 - 開始時の総払出) - (現在の総BET - 開始時の総BET))`

- 8ptベルはBET3pt込みで＋5pt、リプレイは差し引き0pt、ハズレは−3pt。表示が0以下でも開始値を変えず、後の回復を二重計上しない。
- AT結果画面に「AT総獲得（手取り）」を表示。終了結果の表示中は下部カウンターにも同じ値を残し、次の通常ゲームで0へ戻す。
- 無料の0G連・旧セーブの再遊技権は、実際に計上したBETのみ差し引く。画面を毎G更新しないFASTもBET前に開始値を保持する。
- 保存済みのカウンターには以前から払出・BETの開始値が両方あるため、継続中の一連はそのまま再計算できる。途中の再読み込みで開始値を取り直さない。
- 更新前にすでに確定・保存したAT結果カードはそのまま復元し、手取りラベルを後付けしない。新しく発生する結果から新方式になる。
- 特化の「今回／連続特化合計」は獲得した上乗せpt、全員の差枚トリガー結果は台の累計差枚という従来の意味を維持する。
- 遊技履歴・詳細ログは増やさず、既存の開始値だけを利用する。

## 確認

関連78テスト、構文・素材参照・設定チェックを実施。加えて独立した無音のEdgeで、変更前と修正後のPC幅・スマホ幅を比較した。

保存状態の開始値が払出100／BET1,000、途中状態が払出180／BET1,030（手取り50pt）の例で、ベル→リプレイ→ベル→引き戻し5G失敗を操作。最終は全ケースとも払出199／BET1,054だった。

|表示|修正前|修正後|
|---|---:|---:|
|AT終了リザルト|99pt|45pt|
|同時点の下部獲得カウンター|0pt|45pt|

第二ベルのBET後に再読み込みして停止を再開し、BET・払い出しの二重計上がないこと、結果表示中の再読み込みで45ptを維持すること、次の通常ゲームで0へ戻ることを確認。ページ例外・素材読み込みエラーは0件。スマホ幅はブラウザエミュレーションで、実機iPhoneの試験ではない。
