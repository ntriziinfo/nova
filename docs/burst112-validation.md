# version112 検証記録

- 初期150ptを維持し、＋10,000pt到達率を優先する方針を採用。
- 全設定とも30,000G×1,000試行、合計180,000,000G。設定別の集計と95%区間は `burst112-report.md`。
- 設定ごとの冒頭3軌跡・爆発成功3軌跡・挑戦失敗3軌跡を選び、重複を除いた53軌跡をゲーム本体で再生。全軌跡30,000G、計1,590,000Gで、BET・払い出し・初回＋10,000pt到達G・爆発回数・終了状態が試算と完全一致。結果は `burst112-production-parity.json`。
- 抽選・互換性・設定別CZ・モード・機械割表示の関連22テスト合格。HTML構文／参照素材／公開ルート検査合格。
- 全体テスト初回は260件中227件合格・33件失敗。失敗した15ファイルを旧版111のソースへ差し替えた読み取り専用比較でも32件が同じ位置で失敗。今回の仕様変更による1件は古い機械割モデル名の期待値で、採用集計値との照合へ更新して合格。既存32件を今回の合格と扱ってはいない。
- 無音の独立ブラウザーで、成功が第三停止後に確定すること、8,150pt／Lv.5への移行、保存・再読み込みでの保持、失敗時の残り2G→1G→通常AT150ptの遷移を確認。ブラウザーエラーなし。

## 再現

`node scripts/verify-burst112-production.mjs` で代表53軌跡を再生。`--all` を付けると全6,000軌跡を再生する。乱数種と試算時の出玉軌跡の要約は `research/burst112/verified-traces.json`。

旧版のモデルは `research/burst112/baseline111/` に保存。試算用の `scripts/burst112-trial-model.mjs` はこの旧版を読み、実装済みの新ルールを二重に適用しない。大きな試行別AT履歴JSONはローカル保存し、公開用の集計には含めていない。
