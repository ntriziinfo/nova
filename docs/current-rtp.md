# 管理画面・デバッグ機の参考機械割

現行値は公開中の `nova-rtp-current.json` を参照する。`status: ready` の6設定だけが検証済み。`pending` は **未取得（最新仕様の試算待ち）** であり、旧仕様の値や設定目標は表示しない。固定値をこの文書へ転記しない。

## 自動更新

1. main更新時のビルドで `scripts/rtp-current.mjs` が機械割に関わる入力のSHA256を照合する。同一ソースまたは確認済みの表示だけの変更なら、検証済みの値を継続表示する。対応が確認できない変更なら数値を空にして未取得を公開する。
2. 機械割に関わる変更で証跡が無効になった場合だけ、GitHub Actions `Current billion-game RTP` が各設定を独立ジョブで **10億G連続** 試算する。表示だけの変更では試算ジョブをスキップする。日ごとのリセット・MYコンプリート・差枚停止はすべてなし。実遊技の停止条件は変更しない。
3. 6設定すべてが完了し、ゲーム数・BET・払い出し・参考95%区間・最新mainのゲーム仕様が一致した場合だけ、証跡と表示データをmainへコミットする。機械割に関わる入力を変更した旧試算は採用しない。
4. Vercelのmain連携で公開し、管理画面とデバッグ機が60秒ごと・タブ復帰時に再取得する。通信失敗や不正なデータも未取得。古い画面のデバッグ機には異なるゲーム版の数値を混在させない。

入力一覧は `scripts/rtp-current.mjs` の `INPUTS`。抽選モデルだけでなくブラウザの精算・停止制御も監視する。CSS、画像、音源などの表示専用ファイルの変更は再試算の対象外。新たな抽選依存ファイルを追加した場合はこの一覧も更新する。独自設定のデバッグ試算値は「未試算（独自設定）」扱い。

### 表示だけの変更を記録する

`nova-game.js`などに表示処理が混在する場合は、採用証跡のソースとの差分と関連テストを確認し、機械割に影響しない変更だけを `scripts/rtp-presentation-equivalence.json` に記録する。抽選・乱数消費・払い出し・上乗せ・停止結果・ゲーム進行が同じことを確認する。ファイル単位の一括除外やコミットメッセージでの自動判定はしない。

記録は試算元と表示変更後の正確なSHA256、両コミット、理由、確認テストを持つ。登録された組み合わせだけ同じゲーム仕様として扱う。以後そのファイルの抽選や払い出し等を変更するとハッシュが外れるため、従来通り未取得と自動試算に切り替わる。追加の表示変更は元の試算ソースから再確認し、別の正確なハッシュを記録する。承認の連鎖は許可しない。

過去の試算結果・試算元ハッシュ・実行日時は書き換えない。公開データの `sourceVerification` に表示変更の照合記録を残し、`modelHash` は同じゲーム仕様の間だけ維持する。最新の公開コードのコミットは `commit`、元の試算コミットは `sourceCommit` に分けて保持する。

## 証跡と手動実行

`docs/rtp-current-1b.json` が採用証跡。古い証跡はソース不一致で自動的に除外される。旧2.5億G×4系列合算の証跡にも専用検証があるが、新規自動試算は1設定1系列10億G。ブロック区間は100万G×1,000個。

```sh
node scripts/report-rtp-parallel.mjs --games 1000000000 --seed nova-current-SOURCE_COMMIT > result.json
node scripts/rtp-current.mjs adopt result.json SOURCE_COMMIT
```

`--setting 1` などで単一設定を実行できる。CIでは6ファイルを `merge-rtp-current.mjs` で検証・集計する。ソースを固定して実行し、途中で変更された結果を流用しない。試算失敗時は未取得を維持し、Actionsのログから原因を確認して再実行する。

この値は標準設定・取りこぼしなしの長期シミュレーション値であり、1日単位の勝率・万pt率や実際のお客様の払い出し実績ではない。
