# 管理画面・デバッグ機の参考機械割

現行値は公開中の `nova-rtp-current.json` を参照する。`status: ready` の6設定だけが検証済み。`pending` は **未取得（最新仕様の試算待ち）** であり、旧仕様の値や設定目標は表示しない。固定値をこの文書へ転記しない。

## 自動更新

1. main更新時のビルドで `scripts/rtp-current.mjs` が入力ファイルのSHA256を照合する。不一致なら数値を空にして未取得を公開する。
2. GitHub Actions `Current billion-game RTP` が各設定を独立ジョブで **10億G連続** 試算する。日ごとのリセット・MYコンプリート・差枚停止はすべてなし。実遊技の停止条件は変更しない。
3. 6設定すべてが完了し、ゲーム数・BET・払い出し・参考95%区間・最新mainのソースが一致した場合だけ、証跡と表示データをmainへコミットする。入力変更中の旧試算は採用しない。
4. Vercelのmain連携で公開し、管理画面とデバッグ機が60秒ごと・タブ復帰時に再取得する。通信失敗や不正なデータも未取得。古い画面のデバッグ機には異なるゲーム版の数値を混在させない。

入力一覧は `scripts/rtp-current.mjs` の `INPUTS`。抽選モデルだけでなくブラウザの精算・停止制御も監視するため、`nova-game.js`内の表示だけの変更でも保守的に無効となる。新たな抽選依存ファイルを追加した場合はこの一覧も更新する。独自設定のデバッグ試算値は「未試算（独自設定）」扱い。

## 証跡と手動実行

`docs/rtp-current-1b.json` が採用証跡。古い証跡はソース不一致で自動的に除外される。旧2.5億G×4系列合算の証跡にも専用検証があるが、新規自動試算は1設定1系列10億G。ブロック区間は100万G×1,000個。

```sh
node scripts/report-rtp-parallel.mjs --games 1000000000 --seed nova-current-SOURCE_COMMIT > result.json
node scripts/rtp-current.mjs adopt result.json SOURCE_COMMIT
```

`--setting 1` などで単一設定を実行できる。CIでは6ファイルを `merge-rtp-current.mjs` で検証・集計する。ソースを固定して実行し、途中で変更された結果を流用しない。試算失敗時は未取得を維持し、Actionsのログから原因を確認して再実行する。

この値は標準設定・取りこぼしなしの長期シミュレーション値であり、1日単位の勝率・万pt率や実際のお客様の払い出し実績ではない。
