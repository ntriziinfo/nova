# 管理画面・デバッグ機の参考機械割

各設定を独立した2.5億G×4系列、合計10億Gで試算した。2万G・4万Gでのリセット、MYコンプリート、差枚コンプリートは行わない。機械割は4系列の合計払い出し ÷ 合計BET。実遊技のコンプリート条件は変更しない。

- 根拠: `docs/rtp-current-1b.json`。設定別の4系列すべてのBET・払い出し・ゲーム数・乱数seed、1,000個の100万Gブロックによる参考区間、ソースのSHA256を保存する。元レポートSHA256は `70BCD75BBF3A184E81B36039973A0BEF21F8EABB3A8769CDB45D5B446A0BAA5E`。
- 公開: ビルド時に `node scripts/rtp-current.mjs build` で JSON / JavaScript を生成する。
- 検証: 抽選モデルの入力ファイルを基準コミット `e9348409bae5f24511f7cf18c2cf19e7db87bff7` と照合し、全設定10億G・停止条件なし・全24系列の集計整合性を確認する。不一致なら数値を出さず「試算待ち」。UIのみの変更では同じ抽選仕様の検証済みデータを再利用する。
- 更新: ビルド時に抽選入力を照合し、変更があれば自動的に「試算待ち」へ切り替える。新仕様の試算完了後に証跡を採用し、旧数値へ自動で戻さない。
- デバッグ管理画面: `https://nova-eta-jet-30.vercel.app/nova-rtp-current.json` を60秒ごとに取得する。各台の設定に対応する値で全台平均を算出する。他機種の既存表示は維持する。
- デバッグ機: 読み込んだゲーム版と同時に生成したデータを使用する。抽選設定を個別変更した場合は未試算とする。新しいゲーム版を使うには再読み込みが必要。

手動で実行する場合:

```sh
node scripts/report-rtp-parallel.mjs --games 1000000000 --seed nova-current-SOURCE_COMMIT > result.json
node scripts/rtp-current.mjs adopt result.json SOURCE_COMMIT
```

`SOURCE_COMMIT` は試算に使用したコミットIDに置き換える。試算中に抽選コードを変更すると採用時の検証で拒否されるため、コミットの固定チェックアウトで実行する。

現行表は4系列合算の有限ゲーム数による推定値。1日単位の勝率・万pt率を意味しない。ブロックごとのばらつきも根拠データに保持する。`docs/` 内の旧1億G・旧10億Gレポートは当時仕様の履歴であり、現行表示には使用しない。
