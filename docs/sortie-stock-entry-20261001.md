# 出陣ストックの導入演出

出陣で獲得した特化が、次のBETで導入演出なしに1G目を消化していたため、獲得済みの待機キューを1個ずつ「準備→7を狙え→特化」へ通す。

- 準備のBETは表示のみ。次のBETで既存の7狙い動画と停止操作へ進み、全リール停止後の次BETから特化の実ゲームを開始する。準備は最低700ms、停止後は最低500ms表示する。
- 準備と7狙いでは、BET消費・払い出し・実G数・出陣抽選・上乗せ抽選・ゲーム乱数消費を追加しない。7狙いボイスの選択だけ独立した表示用乱数を使う。
- 獲得済みのキャラは再抽選しない。上乗せ性能・保証・裏振り分け・ストック数は維持し、既存エンジンが実ゲーム開始時に1個を消化する。
- 宗介・ギルなどの未表示リザルトがあれば先に表示してから次ストックの準備へ進む。既存の差枚チェックポイントの優先順位は維持する。
- 準備・7狙いの途中・停止後の段階を保存する。AUTOも同じ経路を通り、デバッグ高速試算は演出を省略して従来の抽選エンジンを実行する。
- 出陣のストック当選ゲームでは第三停止後に獲得キャラを高速点滅。裏版は対応する同じキャラ、くしゅり＆にとは2人とも点滅させる。次のBETで解除する。押し順ミスでも内部当選の点滅・ストックは維持する。

検証：関連テスト68件、構文・設定検査、配信素材313点。無音の独立ブラウザで準備と7狙いと停止後それぞれの再読み込み、2ストックの連続消化、獲得ランプ、スマホAUTOを確認。導入演出中の投入・払い出し・実G数・AT状態が不変であることを確認した。

## 現行の出陣抽選（今回変更なし）

`nova-progress.js` の `drawSortie` を、通常・CZ・ボーナス・AT等の実ゲームで1回実行する。小役結果には依存しない。0G連および今回追加した導入演出は分母に含めない。待機中や出陣中の新しい当選権利も予約して、開始可能なタイミングまで保持する。

|設定|出陣権利当選率|
|---|---:|
|1・3・5|1/7,000|
|2・4・6|1/10,000|

10Gの出陣へ入る際、以下の配分で毎Gストック率を1回選択し、その出陣中は固定する。各Gの成立役と別に抽選する。最低2個のストック保証あり。

|設定|10%モード|25%モード|40%モード|60%モード|80%モード|
|---|---:|---:|---:|---:|---:|
|1・3|25%|15%|15%|25%|20%|
|2・4|10%|20%|40%|25%|5%|
|5|47%|5%|5%|5%|38%|
|6|10%|20%|60%|9%|1%|

参照：`nova-tuning.js` の `profile().denominator/tiers`、`nova-art.js` の `beginResearchSortie` と `researchSortieLeft` 分岐、`nova-game.js` の `countTotalSpinIfNeeded`。
