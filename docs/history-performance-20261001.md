# 遊技履歴の軽量化（2026-10-01）

履歴を削除せず、グラフ更新・保存準備・詳細履歴の読み込みを軽量化。
抽選、払い出し、初期pt、減算区間の観測タイミングは変更していない。

- グラフの正規化・並べ替えは復元／配列交換時のみ。通常の追加・同一G更新は最新点と極値だけを更新。
- 同一GのBET後と払出後で最高・最低が戻る場合も、過去全体を走査せず正しく再計算。
- 変更していないグラフのJSONと復帰用の縮約グラフを再利用。設定・統計・途中停止状態は毎回新しく保存。
- 即時の二重保存、保存形式、保存失敗時の警告、既存のグラフ上限／間引き方法を維持。
- 詳細履歴は同じ読み取りトランザクション内で1,000件ずつ読み込む。全件書き出し、集計、未保存レコードの救済を維持。
- 未保存履歴の退避時には、その試打のメタデータだけを取得。過去の全試打を毎回走査しない。
- キャッシュはWeakMapで管理し、リセット・復元で不要になったグラフを保持し続けない。

## 同一PCのEdgeでの比較

人工履歴を使用した隔離・無音ブラウザ。実際のlocalStorage／IndexedDBを使用。
ゲーム内の動画、描画、履歴記録本体を含めたフレーム時間やスマホの計測ではない。
基準コミット：e24db447f569d25511ad28e961f4baff23fe9451。

| 計測対象 | 変更前・中央値 | 変更後・中央値 |
| --- | ---: | ---: |
| 2万点の履歴・停止時の保存 | 8.7ms | 2.3ms |
| 2万点から開始・1回転相当のグラフ更新＋8回保存 | 61.0ms | 20.5ms |
| 6万件の詳細履歴を読み込み、先頭200件を取得 | 3.70秒 | 2.32秒 |

保存計測はウォームアップ5回＋本計測50回、詳細履歴は3回。
1回転相当の計測では、2万点超過後に従来どおりの間引きが入る。
保存データの書き込み回数・履歴件数を削って得た改善ではない。
詳細履歴は引き続き対象試打全体を集計するため、非常に長い履歴の表示には時間がかかる。
