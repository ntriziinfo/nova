## 検査の更新方法

- ファイル名に旧バージョン番号が残るものも、原則として現在の本体を検査する。旧仕様の値を本体へ戻して検査を通さない。
- 過去の承認モデルと比較する検査（v167/v169/v170/v173など）は、指定スナップショットと明示的な調整値を使う。参照中の履歴やスナップショットを削除しない。
- 初期ptは抽選される。支払や保存を単独で検査するときは、残高・設定・保証の消化状況・乱数を固定する。
- 全体の確率検査と、特定の場面の検査を区別する。旧当選率に依存する乱数列を使う場合は、その条件を明示する。
- VMで切り出した関数のUI・監査依存はモックできるが、検査対象の抽選や精算自体をモックしない。表示だけの検査では、実際の獲得権利を検査したことにならない。
- `.test.mjs` 同士をimportしない。共通処理はテストを登録しない補助モジュールに置く。
- 挙動と期待値が違うときは、仕様変更・検査条件不足・本体不具合を確認する。未解決の本体不具合に合わせて期待値を弱めない。

機械割に影響する本体修正は、リポジトリの [作業ルール](../AGENTS.md) に従い、内容と影響の確認を得てから行う。
