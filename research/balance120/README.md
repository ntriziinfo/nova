# 分散型チャレンジ・出玉波形（v120）

v118 / debug v119 (`be2fbb9`) を基準に、BIGを50ptへ短縮し、AT初期ptを増やす。チャレンジをpt獲得型と裏ゾーン獲得型へ分岐させる。pt型は500/1000/2000ptとレベル昇格を独立抽選。Lv.5を保証しない。

通常時のレア役、ATレベル別の性能、選択後の9特化の性能・保証、引き戻し5Gのレア役100%、差枚で抑制しないルールは維持する。通常役のコイン持ち・設定別CZ/初当たり補正・チャレンジ突入係数を調整する。

## 測定

- `model.mjs` は固定コミットのコアに明示的な差分だけを加える。候補は `pilot*.json` に記録する。
- `run.mjs` は乱数系列が独立した30,000G試行を最大4ワーカーで実行する。各試行の全軌跡、初回コンプリート時点、入力ファイルのSHA-256、コミット、シード式を保存する。
- 最終検証は調整と別のシードで各設定3,000試行。機械割と到達率を同じ試行から計算し、両方の採用条件を維持する。
- 実BET・実払い出しで計測し、到達で停止する機械割と停止しない機械割を区別する。未消化ATは払い出しに数えない。
- AT別獲得平均は終了まで観測できたATの集計で、右打ち切りを含む無条件期待値ではない。
- 波形は1,000G区間の差枚分布・500pt以上の上昇/下降割合・最大下落幅を比較する。全30,000G軌跡と実際のコンプリート停止までの観測を区別する。
- raw JSONはローカルに保存し、大容量の試行明細はGitへ含めない。全試行を集計し、都合のよい試行を抜き出さない。

BIG短縮に伴い、4回のベルで払い出し50pt（15+15+15+5）。ネビュラ当選率はベルとの競合ハザードから52%/80%を維持する。上位BIGでも全役確率が非負になるよう生の狙え成功率を50%とし、失敗ナビ50%は維持。BIG専用の色分布を再計算し、表示された青/赤/虹の期待度20/80/100%を維持する。特化ゾーンの色分布は変更しない。

pilot1の候補2件は上位BIGの役確率が負になった不正モデルのため不採用。詳細は `pilot1-invalid.md`。同ファイル内のbaselineジョブは候補変換を通らず、v118の比較データとして有効。pilot2以降は起動時に役確率・総和・BIG突破率を検証する。

画面確認は隔離したヘッドレスEdge、`--mute-audio`、ローカルファイルのリクエスト差し替えを使用する。ユーザーの試打状態や音量には触れない。

pilot6は38G/50ptとリプレイ比率の組み合わせにより設定6のベル確率が負となり、起動時の検証で停止。シミュレーション結果として採用しない。pilot7以降は38.5G/50ptで非負を確認。

最終採用データは `selected-data.json`、実装パラメータは `final-candidate.json`。初期AT300pt、BIG50pt。設定1・5・6はverify、設定2・3・4は再調整後のconfirmを採用。修正前の検証も各設定の全試行単位で保存し、合格値へ混ぜない。初当たり補正とチャレンジ係数は単調増加を要件にせず、設定5はチャレンジ、設定6は初当たりへ配分を寄せて両目標を評価した。

`apply-candidate.mjs` は元コミットと未変更コアを確認して一度だけ適用する。適用後は `report.mjs` → `finalize.mjs` → `report.mjs` で測定値と表示を揃える。`verify-production.mjs` はキャッシュなしの実装で保存シードの全30,000G結果と停止時点を照合する。`qa.mjs` は引数なしで実装、設定JSON引数ありで未適用候補を確認する。`verify-public.mjs` はデプロイ後の配信ソースを照合する。

`plot-data.mjs` は旧版・新版それぞれ3,000試行の最終差枚10/50/90%点を機械的に選択し、同じシードで再現する。`plot.py` で波形画像を生成。波形の個別例と、全試行を使う区間変動の集計を区別する。

`baseline:true` ジョブは実行時の作業ツリーを読むため、旧版の再測定は元コミット `be2fbb9` の別チェックアウトで行う。採用候補は `baseline` を使わず固定コミットから構築する。生データを残していない環境では、対応する採用ジョブを先に再実行する。
